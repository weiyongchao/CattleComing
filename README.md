# 量价罗盘：A 股实时评测

一个零第三方依赖的本地 Web 项目。输入 6 位 A 股代码，读取实时成交价、涨跌幅、成交量及近 30 个交易日行情，以五日均线和五日均量生成可解释的 0–100 分规则评测。

## 启动

要求 Python 3.10 或更高版本：

```powershell
python run.py
```

浏览器打开 <http://127.0.0.1:8000>。也可以指定端口：

```powershell
python run.py --port 8080
```

运行测试：

```powershell
python -m unittest discover -s tests -v
```

## 评分模型

基础分为 50 分，六项信号叠加后限制在 0–100：

- MA5 趋势（±20）：现价相对五日均线的位置。
- 今日动量（±15）：实时涨跌幅。
- 昨日动量（±10）：最近完整交易日的涨跌幅。
- 量比（±10）：当前成交量相对近五日平均成交量；上涨放量加分，下跌放量减分。
- 换手率（±5）：交投活跃度对评分的有限修正。
- 日内位置（±10）：现价处于今日最低价至最高价区间的位置。

评分是透明的启发式规则，不是机器学习预测，也不构成投资建议。盘中累计成交量直接与完整交易日均量比较，早盘量比通常偏低，这是模型边界之一。

页面还会根据评分、MA5、量比、换手率和日内位置，分别生成未持仓建仓参考、已有仓位加仓/持有参考、确认条件、失效条件及动态风险点。操作提示不包含个人风险承受能力、投资期限和整体资产配置，不能替代个人投资决策。

## 打板精选与条件预警（2026-08-31）

- 09:20–09:25先展示动态预选，09:25复核最终观察池，前台最多5只，其余折叠；竞价不直接产生执行仓位。
- 09:30–11:30、13:00–14:57动态复核；09:35后继续扫描昨日首板/连板股，但只补入涨幅至少9%的近封板观察标的，发现时间独立记录，不倒写竞价结果。
- 正式提示默认只有**一只首选**，全天累计最多**5个不同代码**，不是每轮5只；观察池不占名额，不主动弹窗。符合用户“只想买一只、少而精”的偏好，不达标可以一只不选。主板、非ST/退市、上市至少60个交易日、流通市值小于200亿元，并购重组及高异动风险硬剔除。公告未核验、当日资金或五档数据缺失不升级。
- 封板优先：涨停价实际成交、五档无卖盘且有买盘，盘中评分≥80、延续评分≥60、成交额≥5000万元、盘口失衡≥15%、当日主力占比≥-1%。至少两次间隔20秒的有效采样，间断超过90秒、数据缺失或炸板重置。
- 极强开盘例外仅09:30–09:35：已满足原有高换手强竞价连板通道（真实09:25换手>1.2%、高开≥5%、竞价额>5000万元），另需竞价及当前涨幅均在[5%,8.5%)、较开盘≥0.5%、不弱于竞价、盘中评分≥90、延续评分≥75、盘口失衡≥35%、当日主力占比≥3%，且非回踩/晚封/异动观察股；同样需两次采样并成为唯一首选。
- 首选额外门槛：历史延续≥75，潜力评分≥80。公式为历史延续×45% + 盘中确认×30% + 主力占比（限制在0–10）×1.5 + 盘口失衡（限制在0–1）×10；异动观察扣10分、开盘回踩和晚封各扣5分。先封板优先，再按潜力评分择优，页面展示评分依据。该分数不是收益概率或预测盈利。
- 首选仍合格就保持，不随每轮排名波动换票；数据缺失先暂停买点，不立即用备选替换。确认失效后才考虑新首选，失效代码当日不自动回榜。每日名额及首选保存在 `data/board_daily_focus.json`，刷新和重启不重置；记录损坏或写入失败则停止新增提示。当前单进程服务内的并发请求共享锁和记录，不支持多个服务进程共写同一账本。
- 点击“今日只关注这只”后，不再提示其他买点；保留已提示股票的风险监控。锁定不等于已成交、不下单、不加仓；取消锁定也不返还当日名额，下一交易日重新计数。只关注一只不代表满仓。
- 浮窗只提示唯一首选及已提示股票的风险；竞价/普通新增观察固定静默。每个代码每日只发一次正向提示，切换确认类型不重发；风险按代码+条件去重。沿用浏览器旧记录，清空展示记录不清空当日名额。历史/过期数据不触发；移出首选、锁定或60秒没有新扫描后标记为历史记录。风险记录可使总条数超过5，但新股票提示最多5只。
- 预警范围固定为**北京时间今天的正式打板名单**：实时快照日期和服务端首次提示日期均必须是今天。买点、风险、浮窗记录、未读数和打开股票入口共用同一名单；普通观察票、历史票及旧本地缓存股票不能自行加入。竞价快照一律不触发预警；今日名单未确认时先不展示旧缓存。旧记录仅被隐藏，不因升级删除，已使用的当日名额仍保留。
- 策略页或打板页交易时段每20秒尝试刷新；新版服务端同时独立采集，关闭页面不停止后台采集。浏览器浮窗、声音和桌面通知仍需页面运行；支持暂停、隐藏、最小化、拖动及选股打开。不自动下单、不自动撤单。
- 股票详情默认收起：竞价候选、盘中首选、盘前预选、次日预案及策略执行详情均支持单只独立展开/收起。点击股票标题栏操作，收起时保留名称、代码、价格/涨幅、核心结论与高风险标记；展开后查看原有完整数据。浏览器按日期、区域和股票代码记住状态，20秒自动刷新、重排及页面刷新不强制展开，也不影响其他股票。仅保存显示偏好，不改变选股与预警规则。
- 新版接口将当日旧快照转成只读观察视图，原始历史文件不清除、不覆盖。服务重启会清空内存采样计数，需要重新确认。

这些是保守的可解释筛选阈值，尚未证明能提高收益或降低炸板率。两次离散采样不等于期间持续封板，公开行情也可能延迟，成交额/主力分类并非交易所逐笔买卖意图。封单可撤、排队不保证成交，不能回填“开盘买入”的收益。[上交所关于封涨停申报风险的说明](https://www.sse.com.cn/aboutus/mediacenter/conference/c/c_20160722_4146612.shtml)

离线验证：`python -m unittest discover -s tests`、`node tests/test_board_alerts.js`、`node tests/test_board_alert_today.js`、`node tests/test_stock_card_details.js`。浏览器回归可运行 `python tests/board_alert_fixture_server.py`，只在 `127.0.0.1:8001` 提供标注“测试股票”的假数据，不请求行情也不写业务数据；折叠交互回归脚本为 `tests/stock_card_browser_checks.js`。

## 盘中采样留痕与静默验证

- 顶部“采样与静默验证”打开 `/board-research.html`，按日期/代码查询，逐股默认收起并记住展开状态，支持明细分页。本页只读，不启动行情请求或自动扫描。
- 盘中由新版服务端后台采集与页面刷新共用同一轮扫描；关闭页面仍可留痕，服务关闭、午休和非扫描时段不追加。仅记录启用后真实取得的数据，不回填升级前的历史。
- 正式评分、单一首选和全天5只名额不变。新增行情源时间校验：源时间必须为今天、距采集结束不超过60秒、不可超前5秒；重复源时间不增加确认次数，源时间倒退重置。时间缺失/过期或重复时暂停原首选，不能据此立即换票。新数据须同时满足采集间隔和源时间间隔至少20秒，服务端缓存不能冒充第二次确认。
- 行情记录包括源时间、获取时间、价格、成交额、买一与五档、封单金额、资金交易日/源时间（如提供）/获取时间、历史与盘中评分、风险门槛、正式策略判定及实验判定。封单金额只按涨停价买一量（手）×100计算，买一缺失显示未知；资金获取时间不能冒充源更新时间。
- 静默假设 `sealed-shadow-v1`：70≤历史延续分<75，盘中分≥90，沿用原基础质量/公告/异动/资金门槛，完整五档且实际封板；至少4次间隔≥20秒的新行情采样，跨度≥60秒。间断>90秒、数据缺失、炸板或条件失效重置。这个实验独立于正式综合潜力分≥80门槛，只记录假设，不弹窗、不分配名额、不生成交易权限。
- 新增独立结构实验 `early-chain-55-74-v1`：延续分55–74、昨日连续≥2板且早于11:30最终封板，原早封通道匹配、竞价涨幅[1%,9.8%)、竞价额>3000万元、原竞价量能口径>1；盘中分≥90并通过公告/异动/当日资金/完整五档及真实封板核验。55沿用现有历史结构观察线，不是五日回放拟合的盈利阈值。两组各自累计4次新采样、间隔≥20秒且跨度≥60秒，分别保存首次触发，不能串用次数。正式延续分75、潜力分80门槛不变。
- 记录“观察到”的炸板与回封次数；这只是已观察的下限。超过90秒的空档不推断中间发生了什么，不使用盘后最终封板时间，也不把采样跨度称为连续封板时长。首次实验触发的获取时间和参考价持久保存；不是成交记录，不计算虚构收益。收益、可成交性及次日效果回测不在本阶段自动生成。
- 新文件按日追加到 `data/board_research/YYYY-MM-DD.jsonl`，不修改竞价快照、候选历史或正式名额账本。单进程写入加锁、flush/fsync后更新内存；重启恢复去重与首次触发记录。损坏/写入失败时研究通道暂停并显示错误，不清空原文件，不影响正式评分；单日128MB上限，不自动删除记录，不支持多进程共写。
- 只读接口：`GET /api/board-research?date=2026-08-31&code=603269&limit=100&before=101`。code/before可省略，limit为1–500；before为上一页返回的next_before。缺失日期文件返回空记录，不创建文件；损坏文件返回503。
- 验证：`python -m unittest discover -s tests -q`。浏览器回归使用 `tests/board_alert_fixture_server.py` 的隔离临时数据，研究页交互脚本为 `tests/board_research_browser_checks.js`，不请求真实行情。

## 五日规则复核与次日强势目标

- 历史复盘页面、接口和调参统计只展示最近5个已留存交易日，旧磁盘存档暂不删除。窗口不足5日时如实显示覆盖数量，不生成缺失交易日数据。
- 优先检验“T日收盘封板，且T+1收盘相对T日收盘上涨≥5%”。5%是可解释的研究观察线，不是保证盈利的预测；开盘溢价、正收盘溢价和次日涨停单列，各指标使用自身可评样本作为分母。没有成交和退出记录，不能把这些指标称为策略收益。
- 次日未涨停不再自动归为规则失败；次日正溢价、强势、涨停、负溢价和高开回落分开描述。同批候选下跌不能证明大盘环境导致失败，因此取消这种自动市场归因。
- 回放和原始存档明确标识；同一规则版本下还要匹配采集时间、候选代码和关键输入，避免把旧复盘套给新名单。读取时重新生成展示口径，不改写原候选/复盘文件。手工复盘遇到中途快照变化会拒绝覆盖。
- 15:05以前不使用当天尚未收盘的T/T+1日线作完整结果；未来或缺少交易日的T+1数据不进入五日统计。T日未封板但次日上涨仍可展示，不能计为“封板后次日走强”的成功样本。
- 五日结构统计属于描述性对照，样本含重复股票和盘后筛选偏差，不能证明正式买点胜率，更不能保证全对。正式规则不自动读取这些统计调参；少而精，不足条件可以零推荐。并购重组显式标记也做硬剔除，不依赖单一风险等级标签。
- 本次分析见 `reports/2026-08-31-five-day-rule-audit.md`；页面回归脚本 `tests/rule_audit_browser_checks.js`，使用独立临时数据，不连接正式服务。

## 竞价预选与开盘确认（2026.08.31.3）

- 09:17预热；09:20–09:25动态筛选并展示最多5只竞价预选，第一只仅标记“优先观察”。早封连板、高换手连板现可用同一组门槛预选，参考匹配与最终匹配分别保存，不把预选命中当作09:25确认。
- 竞价参考行情必须带今天的源时间，距取数不超过60秒且位于竞价窗口。缺失时间、昨日行情不再用当前系统时间补齐；页面将价量标为参考数据，9:25以实际成交再核验。
- 09:25–09:30形成最终竞价名单并冻结；扫描跨过09:30才完成的结果只能标为“开盘后新增观察”。原始最终名单优先，即使候选为空也不被盘后候选更多的回放替代；行情失败导致的空池不冻结为有效空名单。
- 09:30后重新验证承接、实际封板、完整盘口、当日资金与有效采样。原竞价票可淘汰，盘中新发现单独标来源；首选延续分75/潜力分80、唯一首选和每日累计最多5只均不降低。并购重组继续硬排除，静默实验不直接升级。
- 开盘市场开关在取得至少500只源时间有效的本轮行情后重新计算，沿用原市场门槛；09:25空候选不再永久锁死全日市场判断。没有足够新行情时不伪造市场强势。
- 启动 `python run.py` 默认带后台采集线程：每20秒尝试一轮，API与后台共用锁，不并发重复扫描；网络耗时较长时不会伪称20秒内已完成。只在工作日交易窗口请求，遇休市或未更新行情由日期/新鲜度门槛拒绝，不保证每天必有候选。
- 服务必须持续运行且网络/数据源正常；电脑休眠、服务关闭或行情供应不足都会缺样，不补造信号。`GET /api/board-session` 查看采集状态；`--no-session-worker` 用于离线调试。该采集是应用自身功能，不创建系统计划任务，也不自动启动电脑或下单。
- 修改代码后需重启已有服务才能启用后台逻辑；不自动重启正在使用的实例。单进程部署，不启动第二个进程共写正式账本。
- 回归：`python -m unittest discover -s tests`；`tests/test_board_session.py` 覆盖时段切换、无页面采集、错误恢复、预选门槛、最终冻结、回放隔离及跨日缓存。
